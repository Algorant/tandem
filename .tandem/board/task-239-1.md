## Description

Revise `protocol/plan/spec.md` to implement `decision-11`. The design is settled; do not reopen it.

## Required reading

`decision-11` is the normative source for this change. Read it first.

## Changes

- Remove the accord-to-state synchronization that moves `delivered`/`accepted` into `validation`. Under decision-11, **no accord action moves workflow state except `claim`** moving `todo` to `in-progress`.
- Define `review.status: pending` as the only entrance to `validation`. A manual `move` to `validation` without a pending review is rejected.
- Document the "Request review" and "Accept review / request changes" operations as the active judgment path rather than optional operations tools may pair with a move.
- Specify that review resolution is human-only: an orchestrator may request a review but may not resolve one.
- Specify that `accord rework` clears a pending review.
- Specify that review is requestable independently of accord status, and only at the delegated Task boundary. Not on Subtasks; Epics are exempt.
- Invert the completion policy: `review.status` missing is the normal case for objective work and must be silent. Completing with `review.status: pending` is a hard error.
- Update the workflow diagram and the accord/state mapping table to match.

## Explicitly settled, do not re-evaluate

An earlier draft of this task proposed evaluating a separate "validation reason" field with a closed vocabulary. decision-11 settled this: `review.status: pending` is both the entrance and the reason. Do not add a parallel reason field.
