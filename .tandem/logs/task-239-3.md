## Required reading

## Changes

- `pi-tandem` line 15 currently reads "Use `validation` for delivered work awaiting acceptance." That is now wrong. Delivered work stays in `in-progress` awaiting triage; `validation` means a human was explicitly asked to look.
- Replace permissive framing ("may accept objective non-visual work") with an obligation to verify and complete when the evidence is objective. The observed failure was an agent reading "may" as "optional, therefore not mine."
- State that requesting review is the deliberate act that escalates work to a human, and that an orchestrator cannot resolve its own request.
- State that Workers never run `tandem accord`, `tandem move`, or `tandem complete`; the orchestrator records all transitions from the main checkout. See `papercut-5`: Worker-side board writes land uncommitted in the Worker's worktree and are destroyed at cleanup.
- Add a read-before-assert requirement: never state a task's workflow state in a user-facing summary without reading it first. See `papercut-4`.

## Explicitly settled, do not re-evaluate

An earlier draft proposed requiring "a stated reason when escalating to `validation`." decision-11 settled this: `review.status: pending` is the reason. Do not invent a parallel reason vocabulary.
