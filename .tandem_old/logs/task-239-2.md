## Description

Implement `decision-11` in `tandem/src/`, following the normative spec landed by task-239-1.

## Required reading

1. `tandem decision show decision-11`, **including amendments A1-A4**. A1-A4 correct gaps found during task-239-1; the original consequence list alone is not sufficient.
2. The revised `protocol/plan/spec.md`. It is normative; this task follows it and does not change it.

## Protocol changes

- Remove accord-to-state synchronization for `delivered`, `accepted`, `blocked`, and `failed`. Only two accord actions move workflow state: `claim` (`todo` to `in-progress`), and `rework` on a task in `validation` (clears the pending review and returns it to `in-progress`, per A1).
- Enforce `review.status: pending` as the only entrance to `validation`, including rejecting a direct `tandem move <id> --state validation` without one.
- Allow a task to remain in `validation` with `review.status: accepted` while awaiting completion.
- Review requests are independent of accord status and restricted to the delegated Task boundary: reject on Subtasks, exempt Epics.
- Invert completion policy: silent when `review.status` is missing, hard error `E067` when pending. Remove warning `W020`.

## CLI changes

- Add the `tandem review request|accept|changes|reject <id>` family (A2, A3), including `--json` support consistent with other read/mutation commands.
- `accept`, `changes`, and `reject` require `--reviewer <name>`, recorded in `review.reviewer` with `decidedAt` (A4).
- `changes` and `reject` both resolve the review and return the task to `in-progress`; they differ in recorded status and meaning only.
- Do **not** implement a human-only check. Per A4 it is policy, not validation. If the spec still contains "the resolver is not human" in the resolve mutation's error list, remove that clause as part of this task and say so in your report.
- Update the locked v0 CLI command list in `AGENTS.md` to include the review family.

## Also settle papercut-7

`review.status: not-ready` is specified but has no command that produces it and is indistinguishable from an absent status. Preferred resolution is legacy-readable only, symmetric with the existing treatment of `accord: ready`. Implement that unless the code makes a different answer clearly better, and explain if so.

## Tests

Cover every transition and every rejection path, including: each accord action's effect or non-effect on state; move-to-validation rejection without a pending review; the rework-from-validation path; Subtask review rejection and Epic exemption; completion silent on missing review and erroring on pending; and each review subcommand's recorded status, reviewer, and resulting state.

## Constraints

- Do not change normative semantics. If the spec is ambiguous or contradicts decision-11, stop and report rather than deciding.
- Route durable mutations through shared `app` operations over `project::TandemProject`.
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, and `cargo test` must pass.
